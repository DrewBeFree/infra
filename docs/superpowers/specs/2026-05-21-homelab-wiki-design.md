# DrewBeFree Homelab Wiki — Design

**Date:** 2026-05-21
**Status:** Approved design, pre-implementation

## Goal

A single unified wiki covering the entire DrewBeFree ecosystem — homelab/infrastructure, all projects (apps/sites/agents), and dev workflows/conventions. Private, searchable, low-maintenance, and resistant to drift.

## Decisions (locked)

| Decision | Choice |
|----------|--------|
| Scope | Everything — one unified wiki |
| Top-level structure | Three pillars: Infrastructure, Projects, Workflows |
| Platform | MkDocs Material (markdown source → static site) |
| Hosting | Atlas (PowerEdge), Tailscale-only, served by Nginx |
| Projects catalog | Auto-generated, filesystem-first scan + `repos.json` enrichment |
| Per-app detail | Table index **plus** an auto-generated page per project |
| Repo location | `infra/wiki/` (rides existing `~/infra` clone on atlas) |

## Repo layout

```
infra/wiki/
  mkdocs.yml
  README.md                      # atlas one-time setup notes
  deploy.sh
  scripts/
    gen_catalog.py               # filesystem scan + repos.json + Command Center → projects pages
  docs/
    index.md                     # landing: what this is + links to 3 pillars
    infrastructure/
      index.md                   # homelab overview (machines, network, Tailscale)
      machines.md                # from alienware-vs-poweredge.md
      tools.md                   # from infrastructure-tools.md
      services.md                # what runs where, ports, addresses
    projects/
      index.md                   # AUTO-GENERATED catalog table
      <slug>.md                  # AUTO-GENERATED page per project
    workflows/
      index.md
      conventions.md             # from STRUCTURE.md (naming, dir layout)
      versioning.md              # version mgmt + Command Center rules
      logoff.md                  # logoff checklist
      claude-setup.md            # skills, memory, subagent model rules
```

- Source (markdown + config + scripts) is committed.
- Built `site/` is gitignored (built on atlas at deploy time into `/opt/wiki`).

## Content sourcing

**Infrastructure** — migrate existing infra docs into the four infra pages; the wiki becomes canonical. Leave a one-line pointer stub in each original `.md` (`alienware-vs-poweredge.md`, `infrastructure-tools.md`) so nothing is orphaned and old links still resolve.

**Workflows** — hand-written from `~/.claude/CLAUDE.md`: branching workflow, version management, logoff checklist, subagent model selection, memory/session-log conventions.

**Projects** — generated by `gen_catalog.py` (see below). Never hand-typed.

## `gen_catalog.py` behavior

Filesystem is the source of truth for *what exists*; `repos.json` and the Command Center *enrich*.

1. **Scan** `apps/`, `sites/`, `agents/` for git repos → authoritative project list (catches `bob`, `answering-agent`, and anything added later automatically).
2. **Enrich** each repo from `repos.json` (GitHub URL, type) and from the Command Center `index.html` cards (version, date, status) where present. Fall back to repo `README.md` / `SESSION_LOG.md` for a one-line description.
3. **Emit** `projects/index.md` (sortable table: name, type, version, status, repo link) and one `projects/<slug>.md` per project (description, type, version/status, GitHub URL, local path; screenshots deferred to a later phase).
4. **Warn** on drift: print any repo on disk but missing from `repos.json`, and any manifest entry with no matching directory. Non-fatal — surfaces the staleness instead of hiding it.

Runs as a pre-build step in `deploy.sh`.

## Hosting & deploy

- Served at **`http://atlas/wiki/`** via a new Nginx `location /wiki/` block. Root `/` stays the status dashboard. Tailscale-only — no public exposure.
- `deploy.sh` mirrors the status-dashboard pattern:
  ```bash
  ssh atlas "cd ~/infra && git pull && cd wiki && python scripts/gen_catalog.py && mkdocs build -d /opt/wiki"
  ```
- One-time atlas prerequisites (documented in `wiki/README.md`):
  - `pip install mkdocs-material`
  - `sudo mkdir -p /opt/wiki && sudo chown drew:drew /opt/wiki`
  - add the Nginx `location /wiki/` block and reload Nginx
- `mkdocs.yml` sets `site_url`/`use_directory_urls` appropriately for the `/wiki/` base path.

## Out of scope (v1)

- Public deploy of any section.
- Screenshots/version-history on per-app pages (later phase).
- Search beyond MkDocs' built-in.
- Graph/backlink view.
- Auto-sync of `repos.json` itself (we warn on drift; backfilling is manual).

## Success criteria

- `http://atlas/wiki/` loads over Tailscale with all three pillars navigable and searchable.
- Projects catalog lists every git repo under `apps/`, `sites/`, `agents/` — including `bob` and `answering-agent` — with per-app pages.
- Infra and workflow pages reflect the migrated content; old infra `.md` files point to the wiki.
- A single `./deploy.sh` rebuilds and publishes.
